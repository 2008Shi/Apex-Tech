## 主控最小系统与开源编译链

**功能描述：** 建立可重复的固件工程基线，包括主控最小系统、外设初始化、编译工具链与下载调试链路。工程最终采用全开源工具链，不依赖 ST 官方 CubeMX / CubeIDE 的日常构建流程，但保留 CubeMX 生成的初始化代码与 `lesson2.ioc` 配置。

**开发历程：** 9 月 16 日至 9 月 30 日，电控成员补充 C 语言基础，重点包括指针、结构体与位运算；随后跟随"江协科技"的 STM32 教程学习 GPIO、按键、定时器、PWM、串口与中断。学习顺序按外设依赖排列：先 GPIO 点灯与按键，再定时器与 PWM，最后串口与中断。硬件成员同期练习万用表、面包板与焊接，具体内容见"整机供电与共地"一篇。

10 月 11 日，在 MSYS2 UCRT64 环境中安装 `arm-none-eabi-gcc` 16.1.0、CMake 与 Ninja，打通"配置 — 编译 — 下载"流程。原工程缺失 CMSIS 器件头文件（`stm32f1xx.h`、`stm32f103xb.h`、`system_stm32f1xx.h`），从 ST 官方仓库补齐到 `Drivers/CMSIS/Device/ST/STM32F1xx/Include/`。全量重编译结果为 0 warning / 0 error，产出 `lesson2.elf`。

引脚与定时器初始化代码最初由 STM32CubeMX 生成，`lesson2.ioc` 保留，`MX_GPIO_Init` / `MX_TIM1_Init` 等函数由该配置产生。生成之后编译链路改为上述开源工具链，日常不再打开 CubeIDE。队伍自己的逻辑写在 `USER CODE` 区域与独立的 `.c` / `.h` 文件中，重新生成代码不会覆盖。这一约定的目的是把"生成的初始化"与"手写逻辑"分开：前者可以随时按 `.ioc` 重新生成，后者不依赖 CubeMX 的代码生成顺序。

工程目录的组成如下：

| 路径 | 内容与作用 |
|---|---|
| `crtc/lesson1` | CubeMX 生成的基线工程，用于验证工具链与最小系统 |
| `crtc/lesson2` | 主开发工程：PS2 手柄、DRV8833 电机驱动、麦轮解算、画圆模式、5 路舵机机械臂 |
| `crtc/lesson2_team` | 队友版本工程，用于对照排查与代码合并参考 |
| `tools/*.cfg` | OpenOCD 调试脚本，用于 PS2 时序探测、电机 PWM 检查、失控急停与修复验证 |
| `crtc/tools/zadig.exe` | Windows 下 ST-LINK / libusb 驱动安装工具 |
| `eext` | 预留扩展目录，当前为空 |

本阶段同时确定 PS2 接收器使用 4 根普通 GPIO 做软件模拟 SPI，不使用硬件 SPI2。这样做的直接原因是保留硬件 SPI 资源，并让时序完全由软件控制，便于后续用 OpenOCD 对比不同采样点的原始位流；代价是 CPU 需要参与每一位的翻转，但实测半周期 5 µs 的开销可以接受。该决定为后续定位采样沿错误提供了条件。

**验证与遗留：** 全量重编译 0 warning / 0 error，`lesson2.elf` 可正常下载运行。10 月 17 日 14:55 的最终构建结果为：Flash 14,380 B（text 14,332 B + data 48 B），约 21.9%；RAM 1,936 B（data 48 B + bss 1,888 B），约 9.5%；0 error。当前未启用 UART，PA9 被 TIM1_CH2 占用，调试主要依靠 PC13 状态灯与 OpenOCD 变量监视；是否更换引脚腾出 USART1 排在正赛后评估。
