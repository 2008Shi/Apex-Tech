## PS2 无线手柄通信

**功能描述：** 通过 PS2 2.4G 手柄接收器读取摇杆与按键数据，作为全车唯一的无线控制输入。接收器使用软件模拟 SPI：模式 3（CPOL = 1、CPHA = 1），半周期 5 µs（约 100 kHz），每帧 9 字节。接收器与主控的引脚连接如下：

| 接收器丝印 | STM32 引脚 | 方向 / 说明 |
|---|---|---|
| DAT / DO / MISO | PB12 | 接收器 → 单片机，内部上拉 |
| CMD / DI / MOSI | PB13 | 单片机 → 接收器 |
| CS / ATT / SEL | PB14 | 单片机 → 接收器 |
| CLK / SCK | PB15 | 单片机 → 接收器 |
| VCC | 3.3 V | 禁止接 5 V |
| GND | GND | 必须共地 |

帧内已确认的关键字节包括：下标 2 应为 `0x5A`；下标 1 在进入模拟模式后为 `0x73`；模式字节为 `0x41` 时表示数字模式；下标 7 与下标 8 随摇杆动作变化。数字模式下四个摇杆字节恒为 `0xFF`。

**开发历程：** 接入过程连续遇到两个问题，现象不同，根因也不同。两者的排查过程如下。

**问题一：数据长期为 0xFF，握手无法建立。** 初始排查方向集中在硬件，先后怀疑接收器损坏、5 V 损坏引脚、供电不足导致接收器不稳，并为此在代码中加入 `Servo_IsrDisable()`，理由是"保护 PS2 时序不被中断打扰"。数日无进展后，改用 OpenOCD 脚本同时打印 CLK 下降沿后与上升沿后的原始位流进行对比，问题随即显现：

| 真因 | 具体情况 | 修法 |
|---|---|---|
| 采样沿错误 | 接收器在 CLK 下降沿之后把下一位放到 DAT 上，主机应在低电平中段采样；原代码等待上升沿后才采样，整帧错位一拍，中位 0x80 被读成 0xC0 / 0x3F | 改为下降沿后延时半周期、在低电平中段读取 DAT |
| 掉电退回数字模式 | 接收器供电不稳时退回数字模式，四个摇杆字节恒为 0xFF；0xFF 同时是"摇杆推到底"的合法值，上电后被当成满舵，曾造成四轮全速飞车 | 加双重判据：模式字节 0x41，或四轴同时 0xFF，即判定无真实摇杆数据，四个读取接口一律返回中位 |

修正后握手建立，PC13 状态灯由 5 Hz 快闪变为常亮。此时队伍一度认为问题已经解决，但"能读帧"并不等于"能控车"。

**问题二：帧读取正常，但推摇杆车辆不动。** 状态灯常亮说明 `PS2_Ok` 持续为 1，但左摇杆推动时三个方向的偏移量恒为 0。排查后确认接收器尚未进入模拟模式，模式字节仍为 0x41；数字模式下四轴恒为 0xFF，而上一轮加入的"0xFF 判为无真实数据 → 返回中位"保护正好把这个常量当成了中位，于是偏移量永远为零。换言之，飞车问题被治好了，代价是车辆彻底不动。

修复分两步：上电发送一次模拟模式初始化序列 `0x01 0x42 0x00 ×6`，随后检查 `PS2_Data[1]` 是否为 0x73；若仍为数字模式，则按 100 ms 限流自动补发。限流的目的是避免接收器供电不良时疯狂重发，把它自己搞死。修改后 `PS2_Data[8]` 与 `PS2_Data[7]` 随摇杆动作变化，车辆首次实现手柄控制。

其他容错措施包括：连续 100 ms 读不到有效帧即强制停车；PC13 常亮表示手柄正常，5 Hz 快闪表示读不到手柄。由于 PA9 已被 TIM1_CH2 占用，USART1 无法启用，状态灯成为主要的人机提示手段；在没有串口的情况下，这个灯对区分"通信断了"与"运动解算错了"起了关键作用。

10 月 18 日的 4000 帧实测（约 20 s 真机操作）中，`PS2_Ok` 与 `PS2_Analog` 全程为 1，未出现整帧通信失败。该探针用于把"PS2 解析层"与"后续映射层"分开：只要两个标志全程为 1，就可以排除整帧丢失与解析失败。

调试期间使用的 OpenOCD 脚本包括：`ps2_monitor.cfg` / `ps2_monitor_mine.cfg` 实时监视 PS2 数据、握手标志、电机占空比与引脚电平；`ps2_rawbits.cfg` 对比下降沿后与上升沿后的原始位流；`ps2_speed_sweep.cfg` 在运行期扫描时钟速度；`ps2_gap_probe.cfg` / `read_axes.cfg` 复现"回中后再推无响应"与单轴串扰；`ps2_after_vcc.cfg` / `ps2_haltread.cfg` 检查供电恢复与停机读取状态。

**验证与遗留：** 手柄已能控制底盘完成前进后退、平移与旋转，4000 帧测试未出现整帧通信失败。仍有两个问题未解决：

1. **左手柄串轴。** 只推 LY 时，LX 会从 0x80 漂移到 0xA0 — 0xCD（32 — 77 格），松手后精确回中。后果是"前进"被解算出横移分量，车辆斜向行驶。这是摇杆本体的物理串扰，软件尚未补偿；下一步可加串扰补偿，或更换手柄验证是否为电位器问题。
2. **回中后快速推杆短暂无响应。** 4000 帧探针确认 PS2 解析层未掉线，真因尚未定位，怀疑在 2.4G 链路或后续映射层；需要继续分段排查。

这一过程留下两条经验：其一，"两份不同实现都失败 ⇒ 一定是硬件损坏"是无效推理，两份代码可能共享同一个采样点错误；其二，握手成功只代表能读帧，功能是否可用取决于帧内数值是否合理，两者之间仍可能隔着一个独立问题。
