## 机械臂动作控制与上电安全

**功能描述：** 将手柄按键映射为五路舵机动作，并对上电、限速、超时与断线等情况设置保护，避免舵机堵转烧毁或上电瞬间失控。五路舵机的角色与信号脚如下：

| 代码名 | 型号 | 功能 | 信号脚 |
|---|---|---|---|
| SERVO_BASE | MG995 | 底座水平旋转 | PB8 |
| SERVO_ARM | MG995 | 大臂上下摆动 | PB9 |
| SERVO_WRIST | SG90 | 小臂旋转 | PB10 |
| SERVO_HAND | SG90 | 手部 / 爪子臂转动 | PB11 |
| SERVO_CLAW | SG90（连续旋转） | 爪子张开 / 收回 | PA4 |

当前手柄映射如下：

| 操作 | 功能 | 备注 |
|---|---|---|
| 左摇杆 上下 / 左右 | 前进后退 / 左右平移 | 带 0.4x + 0.6x³ 曲线 |
| 右摇杆 左右 | 底盘原地旋转 + 机械臂底座旋转 | 同一轴复用 |
| △ / × | 大臂上摆 / 下摆 | 每次 3° |
| □ / ○ | 小臂左转 / 右转 | 每次 3° |
| L1 / R1 | 手部正转 / 反转 | 每次 3° |
| L2 / R2 | 爪子正转 / 反转 | 按住转，松手停，最长 1.5 s |
| SELECT | 急停 | R1 已改作手部反转 |

**开发历程：** 10 月 14 日机械臂首次通电时为 4 路舵机，其中夹爪为连续旋转舵机；10 月 17 日的 `servo.c` / `servo.h` 按 5 路实现。首次通电后遇到"按住 L2 转动爪子、再按其他键时爪子被拉回"的问题。原因是 `Arm_Handle()` 在检测到按键变化时，用循环将 5 路舵机角度整体重写，爪子通道也被写入 1500 µs，等于强制停转。修复方式是在批量写角度时跳过 `SERVO_CLAW`，爪子只由对应的两个按键控制。

10 月 16 日对机械臂控制层进行重构，目标是不烧舵机、上电不乱动。重构后的保护参数如下：

| 措施 | 参数 | 作用 |
|---|---|---|
| 上电先发停爪指令 | `CLAW_STOP_US = 1500` | `Arm_Init()` 首先将爪子置为停转脉宽 |
| 全部回中位 | 90° | 五路舵机上电统一回中，姿态可预期 |
| 爪子限速 | `CLAW_SLOW_US = 180`（约 35% 速度） | 不直接给满速，卡住时不易堵转烧线圈 |
| 连续转动超时 | `CLAW_MAX_MS = 1500` | 按键卡住或误操作时 1.5 s 后强制停止 |
| 按键逻辑 | 由边沿触发改为读取当前电平 | 按住才转、松手即停、超时强制停 |

按键逻辑由边沿触发改为读取当前电平，是为了让"按住持续转、松手立即停"成为确定行为。边沿触发在按键抖动或帧丢失时可能产生多次触发，表现为爪子断续转动；读取当前电平则把按键状态与舵机输出直接对应，超时保护再兜住按键卡住的情况。

硬件侧同时确定一条硬性约束：舵机不得从 STM32 的 3.3 V / 5 V 引脚取电。MG995 堵转电流可达 1.5 A，从板载稳压取电会导致主控复位、舵机抖动与 PS2 数据错乱。舵机必须使用独立 5 V 电源，并与主控共地；首次上电前需人工将机械臂摆至中位，避免上电瞬间猛转至 90°。

当前映射存在一处已知取舍：右摇杆 X 同时控制底盘旋转与底座旋转，画圆模式因此不再触发；R1 改作手部反转后，急停仅保留 SELECT。该映射需在正赛前结合比赛任务再评审一次，确认取物、转底盘与转底座三种操作不会互相干扰。

按键映射的确定不是一次完成的。早期曾把圆圈键用于画圆模式，后来因为机械臂需要小臂右转，将该键改作小臂控制；R1 原用于急停，后来改作手部反转，急停只保留 SELECT。每次改键都同步修改了 `Arm_Handle()` 的分支与接线文档，避免代码与操作说明不一致。当前映射的验证方式是逐个按键单独测试，再做多关节组合动作，最后在松手静置状态下确认非初始角度保持不变。手柄断线时，控制层强制写入停止脉宽，不让舵机保持最后一条指令。

**验证与遗留：** 5 路舵机均能在 0 — 180° 内动作，上电统一回中位；爪子按住才转、松手即停、1.5 s 超时，不再自转。各关节的实际可用角度与机械限位尚未逐一标定，存在顶死与堵转风险，已列入 P0 待办。进阶的夹爪限位保护单独记录在"夹爪限位保护"一篇。
