## 麦克纳姆轮全向运动解算

**功能描述：** 将前进、横移与旋转三个运动分量解算为四个麦克纳姆轮的转速与方向，使车体能够前进后退、左右平移与原地旋转。解算采用标准麦克纳姆轮公式：

```
M1 = vx + vy + omega
M2 = vx - vy - omega
M3 = vx - vy + omega
M4 = vx + vy - omega
```

其中 `vx` 为前后分量，`vy` 为左右分量，`omega` 为旋转分量；四个轮子的安装位置与转向约定在底盘建模阶段已经固定，解算符号与 `WHEEL_INVERT_*` 配置必须和实际安装一致。

**开发历程：** 代码完成后，公式复核三遍均未发现错误，但车辆无法横移：推左右摇杆时车体斜向运动，四个轮子看起来都在转，却没有产生纯侧向位移。排查持续两天，最初怀疑解算符号、定时器通道映射与电机接线，逐项排除后确认问题在机械安装。

四个麦克纳姆轮的辊子方向被装成了一致，而正确安装应使辊子轴线在俯视方向呈 X 形。方向一致时，四个轮子的侧向分力互相抵消，物理上不可能产生横移；此时无论代码如何修改，车辆都不会横移。将左右两侧轮子对调，并对 `WHEEL_INVERT_*` 中相应两轮取反后，运动恢复正常。

这一问题的排查过程说明，运动学公式正确并不等于机械安装正确。公式、电气与机械是三个独立层面；代码复核只能证明公式与符号自洽，不能证明轮子装对了方向。后续将"架空确认四轮转向与取反"固定为落地测试前的必要步骤。

本阶段尚未接入手柄，速度以常量直接写入代码。四个轮子的转向、取反关系与解算符号全部在架空状态下校正完成，车辆已经能够直线行驶与横移。由此形成两条纪律：先架空试转向，再落地试跑；手柄作为独立变量，不与运动学问题混在一起排查。

**验证与遗留：** 10 月 18 日录制"底盘运动（全部）"时，第一次只拍摄了前进后退，未包含横移与原地旋转，无法证明全向能力，随后补拍。最终视频包含前进后退、左右平移与原地旋转三类运动，并与 PS2 手柄同框，便于评委确认是遥控而非预编程。

当前底盘为开环控制，没有编码器与 IMU。四轮实际转速差异、地面摩擦与电池电压变化都会影响直线与画圆形状；`WHEEL_TRIM_*` 需要在实车上逐轮标定，trim 差异超过 ±10% 时画圆会被拉成椭圆。长距离直线偏差的根治方案是增加编码器做速度闭环，排在正赛前的 P2 优先级。
